## Quest Soft-Delete Final Shape

Chose `isActive=false` over a separate `deletedAt` column because:
1. Quest model already has `isActive` — no migration needed.
2. The `audit_log.payload.after.intent` field carries the disambiguation — readers can distinguish `QUEST_DELETE` (intent=delete) from `QUEST_DEACTIVATE` (no intent field) at audit-log read time.
3. Public Quest reads on the user side already filter by `isActive=true`, so soft-deleted quests disappear from the catalog without any further code change.

## DeckCard Cleanup Ordering Inside Revoke Tx

```js
async (tx, setAudit) => {
  const before = await tx.userCard.findUnique({
    where: { id }, include: { deckCards: true },
  });
  if (!before) throw new AppError('NOT_FOUND', 404);
  // FK cleanup BEFORE userCard.delete (T-04.5-03-01).
  await tx.deckCard.deleteMany({ where: { userCardId: id } });
  await tx.userCard.delete({ where: { id } });
  setAudit({
    before: { /* … */, deckCardCount: before.deckCards?.length || 0 },
    after: null,
  });
  return { id, deleted: true };
}
```

Even though Migration A adds `onDelete: Cascade` on `DeckCard.userCardId`, the explicit `deleteMany` is kept because:
- The audit payload needs the slot count; it's natural to capture it during the read.
- It keeps the contract grep-able (`grep -q "deckCard.deleteMany"` is in the regression-guard chain).
- Rollback semantics: if `writeAudit` throws, both `deleteMany` and `delete` roll back together inside the same tx.

## BankCard Force-Issue Cross-Check Pattern

```js
const account = await req.prisma.bankAccount.findUnique({
  where: { id: accountId }, select: { id: true, userId: true },
});
if (!account) throw new AppError('VALIDATION_FAILED', 400, 'Счёт не найден');
if (account.userId !== userId) {
  throw new AppError('VALIDATION_FAILED', 400, 'Счёт принадлежит другому пользователю');
}
```

The check runs OUTSIDE the `withAudit` tx — failure short-circuits before any side-effect and no audit row is written. Test case `POST force-issue rejects accountId belonging to a different user` asserts `audits.length === 0` after a 400 response.
