The test runs each parametrized case with `truncateAll()` between tests, monkey-patches `auditLog.writeAudit` to throw, executes the route with a valid admin JWT + minimal valid body, asserts the response is 5xx, and asserts a per-domain DB snapshot is unchanged (no row written, deleted, or mutated; balance unmoved).

Plus 3 non-parametrized tests:
- **Test 0 (sanity)** — enumerator returns >= 20 routes (>= 33 in practice).
- **Test 4 (read-only control)** — `GET /api/admin/dashboard` returns 200 even when `writeAudit` throws (proves the harness discriminates between mutations and reads).
- **Test 5 (cleanup)** — `auditLog.writeAudit` reference is restored after each test (no `simulated_audit_failure` sentinel in the function source).

**Routes added by Plans 2-5 BEYOND Plan-6 planning-time anticipation:** None. The fixture map in `buildFixturesFor` covers every route the enumerator returns; no route hit the `default → return null → Fixture missing` gate. The cardTemplates POST/PUT/DELETE routes (mounted at `/cards`) were noted in Plan 1's interfaces but the planning-time prose understated the count — Plan 6 picked them up via `DOMAIN_TO_MOUNT` and added their fixture entries in this same commit (per Task 1 Step C contract).
