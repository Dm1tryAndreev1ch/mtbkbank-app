### withAudit + AUDIT_ACTIONS (Task 1)

`backend/src/services/auditLog.js` gains:

```js
async function withAudit(prisma, ctxBase, mutationFn) {
  return prisma.$transaction(async (tx) => {
    let auditExtras = {};
    const setAudit = (extras) => { auditExtras = { ...auditExtras, ...extras }; };
    const result = await mutationFn(tx, setAudit);
    await module.exports.writeAudit(tx, { ...ctxBase, ...auditExtras });
    return result;
  });
}
```

The `module.exports.writeAudit` reference (instead of the local closure) is
the Pitfall-2 fix: Plan 6's rollback test will monkey-patch `auditLog.writeAudit`
to throw and assert that the surrounding mutation rolls back. Destructured
imports freeze the function reference and break that contract — every admin
sub-router consequently uses `const auditLog = require('../../services/auditLog')`
(module reference, never destructure).

`AUDIT_ACTIONS` is a frozen 35-entry codebook covering the 28 codes from
CONTEXT D-05 plus 7 grandfathered codes already in use (USER_UPDATE,
USER_CREATE, CARD_TEMPLATE_CREATE/UPDATE/DELETE, CARD_GRANT,
TRANSACTION_SIMULATE) so the migrated handlers keep emitting the same
action strings.

Unit-tested in `backend/tests/unit/auditLog.test.js` (4 tests):
commit-on-success, rollback-on-mutation-throw, rollback-on-writeAudit-throw,
setAudit merge into ctxBase, AUDIT_ACTIONS frozen, exports surface unchanged.

### Admin SPA primitives (Task 5)

`admin/src/components/ConfirmDialog.jsx` extended with two new optional
props per UI-SPEC §"Hard-delete typed-confirmation":

```jsx
<ConfirmDialog
  requireTypedConfirmation={user.phone}
  typedPrompt={`Введите номер телефона ${user.phone} для подтверждения:`}
  /* …existing props… */
/>
```

When `requireTypedConfirmation` is truthy, a labeled `<input>` renders and
the confirm button stays disabled until `typed === requireTypedConfirmation`
exactly (case-sensitive). Pressing Enter inside the input fires `onConfirm`
when valid. The typed state resets to `''` on every `open` transition
false → true. Default Russian prompt:
`Введите ${requireTypedConfirmation} для подтверждения:`. Escape baseline
preserved.

`admin/src/components/EmptyState.jsx` (NEW) — shared 240px-tall empty-state
primitive used by every list page in Plans 2-5 per UI-SPEC §State Matrix.

heading + body. Tokens via `index.css` custom properties — no inline hex
literals.

`admin/src/lib/auditCodebook.js` (NEW) — 28-entry codebook mapping the
English snake-uppercase audit `action` codes (stored verbatim in DB per
CONTEXT D-05 lock) to Russian display labels + destructive marker, per
UI-SPEC §"Audit-Log Dashboard Widget". Plan 4's dashboard widget consumes
`actionToRussianLabel(code)` and `actionIsDestructive(code)`.

**3. [Rule 2 — Critical] D-02 allowlist breadth**

## Known Stubs

The 8 placeholder sub-routers (accounts, decks, limits, notifications,
payments, quests, subscriptions, trades) export bare `express.Router()`
instances with no routes wired. This is **intentional**: each is owned by a
downstream plan (2-4) per CONTEXT D-09. Plans 2-4 will fill them with
their domain CRUD endpoints. Mounting the empty routers in `index.js` is
safe — Express returns 404 for any unmatched path, and the existing legacy
endpoints (`/cards`, `/grant-card`, `/simulate-transaction`,
`/users/:id/accounts`) keep working because they are mounted at the index
level alongside the empty domain routers.

The `backend/eslint-rules/no-admin-prisma-outside-admin.js` file is an
intentional placeholder — the rule's source of truth lives in
`eslint.config.js` as flat-config selectors per RESEARCH §Pattern 3 option A.
The empty file reserves the path in case a future phase migrates to a
plugin-style rule. Documented inline.
